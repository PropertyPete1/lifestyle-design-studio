# YouTube Comment Auto-Reply

Replies to new comments on the LDR YouTube channels with a short, natural,
per-comment reply generated by Claude, pointing viewers to the link in bio.

Runs on a GitHub Actions cron every 20 minutes. State lives in an AES-256
encrypted SQLite DB on the orphan `state` branch — the same pattern as
LDR-Automation-Clean.

---

## GitHub secrets to add

Repository → **Settings → Secrets and variables → Actions → New repository secret**.
Exact names, all four required:

| Secret | Value |
| --- | --- |
| `YT_CLIENT_ID` | OAuth2 client ID (Google Cloud → APIs & Services → Credentials) |
| `YT_CLIENT_SECRET` | OAuth2 client secret |
| `YT_REFRESH_TOKEN` | Refresh token for the channel-owning Google account, scope `https://www.googleapis.com/auth/youtube.force-ssl` |
| `YT_STATE_ENCRYPTION_KEY` | Any long random passphrase you invent — the AES-256 key for the state DB. Generate with `openssl rand -base64 32`. Nothing else uses it; if you lose it the reply history is unrecoverable and the bot re-replies to old comments. |

Already present in this repo, reused as-is — **do not re-add**:

| Secret | Used for |
| --- | --- |
| `ANTHROPIC_API_KEY` | Claude reply generation |

Optional repository **variable** (not a secret): `YT_LLM_MODEL` to pin a
different model. Defaults to `claude-opus-5`.

> These are deliberately separate from the existing `GOOGLE_CLIENT_ID` /
> `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN` used by the auto-poster. That
> token carries Drive + Gmail scopes, not `youtube.force-ssl`, and overwriting
> it would break daily posting.

## Config

`config/channels.yaml` — one entry per channel. Replace the three
`UC_REPLACE_WITH_...` placeholders with real channel IDs (YouTube Studio →
Settings → Channel → Advanced settings). Until you do, the workflow runs and
exits cleanly without doing anything.

Each channel takes an optional `voice:` block so San Antonio, Austin, and DFW
can sound distinct. Omit it and the channel uses `defaults.voice`.

Knobs, all under `defaults:`:

| Key | Default | Meaning |
| --- | --- | --- |
| `max_comment_age_days` | 14 | Skip comments older than this |
| `max_replies_per_run` | 20 | Hard cap per workflow run |
| `max_replies_per_day` | 100 | Rolling 24h cap (quota protection — see below) |
| `min_seconds_between_replies` / `max_seconds_between_replies` | 3 / 5 | Random pause between replies |
| `skip_if_reply_count_at_least` | 1 | Skip threads that already have replies |

## What gets skipped

Logged per run with counts, and visible in the digest footer:

- already replied to (the `replied_comments` ledger)
- our own comments — without this the bot replies to its own replies forever
- threads that already have any reply (manual answer, or a run whose state push failed)
- comments with replies disabled
- older than `max_comment_age_days`
- emoji-only, symbol-only, or under 4 characters of real text (keycap emoji included)
- anything containing a link (URL, bare domain, `t.me`, `wa.me`, shorteners)
- spam signals: sub4sub, channel promo, contact details, phone/email, crypto/money pitches, all-caps, hashtag stuffing, character spam, walls of text

## Reply generation

`claude-opus-5`, no template. Each call gets the comment text, the video title,
the channel's voice tag, and **the last 25 replies posted** with an instruction
not to reuse their openings or sentence shapes — that's what keeps replies from
converging on one phrasing.

Every generated reply is validated before it can be posted: under 280 chars,
no URL/phone/email, no assistant-voice or internal-tag leakage, single
paragraph, and it must actually point at the bio link. Up to 3 attempts; if
none pass, the comment is left alone rather than getting a canned fallback.

## Quota

YouTube Data API default is 10,000 units/day. `commentThreads.list` costs 1
unit, `comments.insert` costs 50. Scanning 3 channels every 20 minutes is
~220 units/day. The `max_replies_per_day: 100` cap bounds posting at 5,000
units/day, leaving headroom. On `quotaExceeded` the run stops early and leaves
the remaining comments eligible for the next pass.

## Run it manually

Actions → **YouTube Comment Auto-Reply** → Run workflow. The `dry_run` input
generates replies and logs them without posting anything.

Locally:

```bash
cd yt-comments
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
export YT_CLIENT_ID=... YT_CLIENT_SECRET=... YT_REFRESH_TOKEN=... ANTHROPIC_API_KEY=...
DRY_RUN=true ./.venv/bin/python run_reply_pass.py
```

## Tests

```bash
cd yt-comments && python3 -m unittest discover tests -v
```

33 tests over the filters, reply validation, and the state ledger. No network,
no credentials needed.

## Files

```
yt-comments/
  config/channels.yaml          channel list + voice tags + knobs
  run_reply_pass.py             entry point
  src/yt_comments/
    config.py                   env + YAML settings
    state.py                    encrypted-at-rest SQLite: replied_comments, runs
    oauth.py                    refresh-token -> access-token exchange
    youtube.py                  commentThreads.list / comments.insert
    filters.py                  emoji / spam / link / age / self screening
    replies.py                  Claude reply generation + validation
    digest.py                   weekly Markdown digest
    main.py                     the pass itself
  tests/                        offline unit tests
.github/workflows/yt-comments.yml
.github/actions/yt-state-sync/action.yml    AES-256 pull/push of state
```

State branch holds `yt-comments/data/yt_comments.sqlite3.enc` (encrypted) and
`yt-comments/data/weekly_digest.md` (plain Markdown — no credentials in it, and
being readable straight from the branch is the point).
